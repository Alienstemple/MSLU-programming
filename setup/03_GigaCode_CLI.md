# GigaCode CLI

**К занятиям 13–17 и итоговому проекту.**

> ⚠️ Названия команд и пунктов интерфейса могут отличаться от описанных.
> Источник истины — **https://gitverse.ru/features/gigacode/install/** и
> **https://gitverse.ru/docs/ai/ai-assistant-gigacode/**. О расхождениях сообщать преподавателю.

## Что это

ИИ-ассистент разработчика от Сбера, работающий в терминале в контексте папки проекта.
Аналог Claude Code и Codex CLI, работает без VPN.

| Чат в браузере | Агент в терминале |
|---|---|
| код переносится копированием | читает файлы проекта сам |
| не знает структуры проекта | видит структуру целиком |
| не проверяет результат | запускает код и читает ошибку |
| даёт совет | вносит изменения, создаёт файлы |

Отсюда требование к постановке задачи: агенту нужна спецификация, а не формулировка в одну
строку. См. `agent/Памятка_агентская_разработка.md`.

## Шаг 0. Требования

1. **Аккаунт GitVerse** (`gitverse.ru`, регистрация через Сбер ID). Агентский режим доступен
   авторизованным пользователям бесплатно.
2. **Node.js ≥ 18** — LTS-версия с **https://nodejs.org/**, настройки по умолчанию.

*Проверка* в новом окне терминала:

```
node -v
npm -v
```

## Шаг 1. Установка

```
npm i -g @sber/gigacode-cli
```

`-g` — глобальная установка, команда доступна из любой папки.

| Ошибка | Решение |
|---|---|
| Windows, `EACCES` / «отказано в доступе» | запустить PowerShell от имени администратора |
| macOS, `EACCES` | `npm config set prefix ~/.npm-global`, добавить `~/.npm-global/bin` в `PATH`, повторить |

*Проверка:* `gigacode --version` печатает номер версии.

## Шаг 2. Авторизация

```
gigacode auth login
```

Откроется браузер (либо будут показаны ссылка и код) — войти в GitVerse и подтвердить доступ.
Если браузер не открывается: получить токен доступа в настройках профиля GitVerse и ввести
по подсказке в терминале.

> 🔒 Токен эквивалентен паролю: не отправлять в чат, не вставлять в код, не коммитить.
> При компрометации — отозвать в личном кабинете и создать новый.

*Проверка:* `gigacode` без аргументов открывает диалог, а не ошибку авторизации.

## Шаг 3. Запуск в проекте

Агент видит папку, из которой запущен. Запускать только внутри папки проекта.

```
cd путь/к/mglu-project
gigacode
```

Начинать с запросов на понимание, а не на генерацию:

```
Опиши, что делает этот проект и из каких файлов состоит.
```
```
Прочитай файл search.py и объясни, что происходит в функции build_index.
```
```
В файле tokenize.py есть ошибка на пустом входе. Найди её и объясни, не исправляя.
```

## Команды

| Команда | Действие |
|---|---|
| `gigacode` | диалог с агентом в текущей папке |
| `gigacode --version` | версия |
| `gigacode auth login` / `logout` | вход и выход |
| `gigacode review` | ревью текущих изменений |
| `gigacode --help` | полный список команд установленной версии |

Набор команд меняется от версии к версии; актуальный список даёт `gigacode --help`.

## Правила работы

Подробно — `agent/Памятка_агентская_разработка.md`. Кратко:

1. **Малый шаг.** Одна задача — один запрос — одна проверка — один коммит.
2. **Сначала план.** «Предложи план, не пиши код», обсудить, затем разрешить реализацию.
3. **Под контролем версий.** Коммит до запуска агента; откат — `git restore .`.
4. **Не принимать непонятый код.** Спрашивать «объясни эту строку», «что будет на пустом
   списке». Понимание кода входит в оценку на защите проекта.

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `gigacode: command not found` | `PATH` не обновился после установки | перезапустить терминал; проверить `npm -v` |
| `401 Unauthorized` | токен недействителен | `gigacode auth logout`, затем `login` |
| `npm ERR! EACCES` | нет прав на глобальную установку | см. шаг 1 |
| Агент не видит файлы | запущен не из папки проекта | `cd` в папку проекта, запустить заново |
| Агент изменил больше, чем нужно | задача сформулирована слишком общо | `git restore .`, разбить задачу на шаги |
