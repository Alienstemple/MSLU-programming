# Git и GitHub/GitLab

Git — система контроля версий: хранит историю изменений файлов проекта,
позволяет вернуться к любому сохранённому состоянию и увидеть, что именно изменилось.

Для курса важны три применения: откат после неудачных правок, просмотр изменений, публикация проекта по ссылке.

## Термины

| Термин | Значение |
|---|---|
| **репозиторий** (repo) | папка проекта под управлением Git |
| **коммит** (commit) | сохранённое состояние проекта + сообщение об изменении |
| **staged** | отобрано для следующего коммита |
| **ветка** (branch) | параллельная линия истории |
| **remote** | копия репозитория на сервере (GitHub, GitVerse) |
| **push / pull** | отправить коммиты на сервер / забрать с сервера |


## Шаг 1. Установка

### Windows

1. **https://git-scm.com/download/win**, запустить установщик.
2. Настройки по умолчанию подходят. Редактор по умолчанию имеет смысл сменить на
   «Use Visual Studio Code as Git's default editor».

*Без прав администратора:* на той же странице — **Portable (thumbdrive edition)**.

### macOS

```
git --version
```

macOS предложит доустановить инструменты разработчика. Иначе — установщик с
**https://git-scm.com/download/mac**.

*Проверка (обе системы):* в новом окне терминала `git --version` печатает `git version 2.x.x`.

## Шаг 2. Настройка (один раз)

```
git config --global user.name "Иванова Анна"
git config --global user.email "anna@example.com"
git config --global init.defaultBranch main
```

Почта — та же, что у аккаунта GitHub/GitVerse.

*Проверка:* `git config --global --list` показывает имя и почту.

## Шаг 3. Создание репозитория

В папке проекта:

```
git init
```

Появляется скрытая папка `.git` — вся история. Не удалять.

### .gitignore

Создать в корне проекта файл `.gitignore`:

```gitignore
# виртуальное окружение
.venv/
venv/

# служебные файлы Python
__pycache__/
*.pyc

# служебное от ноутбуков
.ipynb_checkpoints/

# системный мусор
.DS_Store
Thumbs.db

# секреты
.env
*.key
token.txt
```

Ключи и пароли в репозиторий не попадают: удаление их из истории требует переписывания
всех последующих коммитов.

## Шаг 4. Основной цикл

```
git status                     # что изменилось
git add имя_файла.py           # отобрать файл
git add .                      # отобрать всё изменённое
git commit -m "Добавил чтение файла корпуса"
git log --oneline              # история
```

Сообщение коммита должно отвечать на вопрос «что изменилось»:

| Плохо | Хорошо |
|---|---|
| `фикс` | `Исправил падение на пустом файле` |
| `изменения` | `Добавил стоп-слова в токенизатор` |

*Проверка:* после `git commit` строка видна в `git log --oneline`.

## Шаг 5. Отмена изменений

| Ситуация | Команда |
|---|---|
| Вернуть файл к последнему коммиту | `git restore имя_файла` |
| Отменить `git add` | `git restore --staged имя_файла` |
| Отменить последний коммит, изменения оставить в файлах | `git reset --soft HEAD~1` |
| Вернуть весь проект к последнему коммиту | `git reset --hard HEAD` ⚠️ несохранённое удаляется |
| Посмотреть изменения | `git diff` |
| Посмотреть файл из прошлого коммита | `git show HEAD~1:имя_файла` |

⚠️ `--hard` удаляет незакоммиченную работу без подтверждения. Перед вызовом — `git status`.

## Шаг 6. Ветки

Ветка изолирует эксперимент от рабочей версии. Основной сценарий — запуск ИИ-агента по проекту.

```
git switch -c experiment       # создать ветку и перейти
git switch main                # вернуться к рабочей версии
git branch -D experiment       # удалить неудачную ветку
```

Принять результат эксперимента:

```
git switch main
git merge experiment
```

## Шаг 7. Удалённый репозиторий

- **GitVerse** (`gitverse.ru`) — работает без VPN, там же регистрация для GigaCode. Основной
  вариант курса.
- **GitHub** (`github.com`) — может требовать VPN.

1. Зарегистрироваться.
2. **Создать репозиторий**, задать имя (`mglu-project`), выбрать приватный или публичный.
3. Выполнить команды, показанные сайтом:

```
git remote add origin <адрес_репозитория>
git branch -M main
git push -u origin main
```

4. При первом `push` вместо пароля указывается **токен доступа** (Personal Access Token) из
   настроек профиля. Токен показывается один раз — сохранить вне репозитория.

Далее отправка изменений — `git push`.

## Git в интерфейсе VS Code

Панель **Source Control** (`Ctrl/Cmd + Shift + G`):

- список изменённых файлов, клик показывает построчную разницу;
- `+` у файла — `git add`;
- поле сверху — сообщение коммита, галочка — `git commit`;
- «…» → Push — `git push`.
