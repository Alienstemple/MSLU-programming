## 1. `for`: обход коллекции

```python
for item in items:
    print(item)
```

`for` проходит по элементам коллекции. Индекс при этом не нужен, и это отличает
Python от C-подобных языков.

Когда индекс всё-таки нужен, берут `enumerate`, а не `range(len(...))`:

```python
for i, item in enumerate(items):
    print(i, item)

for i, item in enumerate(items, start=1):   # нумерация с единицы
    print(i, item)
```

`range` порождает последовательность целых:

```python
range(5)          # 0 1 2 3 4
range(2, 5)       # 2 3 4
range(0, 10, 2)   # 0 2 4 6 8
range(5, 0, -1)   # 5 4 3 2 1
```

Правая граница не включается. Отсюда `range(len(items))` даёт корректные индексы,
а `range(1, len(items))` пропускает первый элемент.

## 2. Накопитель и счётчик

Два приёма, на которых стоит половина всего кода.

```python
total = 0                 # накопитель создаётся ДО цикла
for value in values:
    total += value

count = 0
for value in values:
    if value > 0:
        count += 1
```

Создание накопителя внутри цикла обнуляет его на каждом шаге, и результатом
окажется вклад последнего элемента. Ошибка не даёт сообщения.

Для суммы, максимума и подсчёта в Python есть готовые функции, и в рабочем коде
берут их:

```python
total = sum(values)
biggest = max(values)
count = sum(1 for v in values if v > 0)
```

Писать цикл руками стоит, когда на каждом шаге происходит что-то ещё.

## 3. `while`

```python
while condition:
    ...
```

`for` применяют, когда число шагов известно заранее, `while` когда неизвестно.

Две типовые формы из главы 4 Гэддиса.

**Сигнальная метка.** Специальное значение означает «данные кончились».

```python
line = read_next()
while line != "":
    process(line)
    line = read_next()      # чтение повторяется в конце тела
```

Чтение стоит и до цикла, и в конце тела. Иначе первое значение либо не проверится,
либо потеряется.

**Валидация ввода.** Спрашивать, пока не дадут годное.

```python
n = int(input("Count: "))
while n <= 0:
    print("Positive number expected.")
    n = int(input("Count: "))
```

`break` выходит из цикла немедленно, `continue` переходит к следующей итерации.
Оба удобны и оба усложняют чтение, поэтому применяют их экономно.

## 4. Вложенные циклы

Внутренний цикл прокручивается целиком на каждом шаге внешнего.

```python
for a in items:
    for b in items:
        ...              # тело выполнится len(items) ** 2 раз
```

Здесь живёт главный источник медленного кода. При росте данных в 10 раз работа
растёт в 100 раз. На тысяче элементов это миллион операций, на миллионе триллион.

Правило на первое время: увидели цикл в цикле по одним и тем же данным,
остановитесь и проверьте, нельзя ли обойтись одним проходом. Обычно можно,
и этому посвящены занятия 6 и 9.

## 5. Функция

Функция даёт имя куску работы и описывает контракт: что принимает, что возвращает.

```python
def count_words(text):
    """Возвращает число слов в строке."""
    return len(text.split())

result = count_words("one two three")
```

Три части: имя, параметры, возвращаемое значение. Строка сразу после `def`
называется docstring и описывает контракт для человека.

### Аргументы

```python
def clip(value, low=0, high=100):     # low и high имеют значения по умолчанию
    return max(low, min(value, high))

clip(150)                 # 100
clip(150, high=200)       # 150, аргумент передан по имени
```

Значение по умолчанию вычисляется один раз при определении функции.
Изменяемый объект в этой роли даёт классическую ловушку:

```python
def bad(item, acc=[]):    # список создаётся ОДИН раз
    acc.append(item)
    return acc

bad(1)     # [1]
bad(2)     # [1, 2], тот же список
```

Правильно писать `acc=None` и создавать список внутри.

### `return` против `print`

```python
def add_bad(a, b):
    print(a + b)          # показывает результат, но не отдаёт его

def add_good(a, b):
    return a + b          # отдаёт значение вызывающему

x = add_bad(2, 3)         # x равен None
y = add_good(2, 3)        # y равен 5
```

Функция без `return` возвращает `None`. Путаница этих двух вещей даёт
`TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'`
в неожиданном месте.

`return` завершает функцию немедленно. Несколько `return` в одной функции
это нормально, часто так короче.

## 6. Область видимости

Имя, созданное внутри функции, снаружи не существует.

```python
def f():
    local_value = 1
    return local_value

f()
print(local_value)      # NameError
```

Это защита: у двух функций могут быть одинаковые внутренние имена,
и они друг другу не мешают.

Функция видит внешние имена, но присвоить им не может. Присваивание создаёт
новое локальное имя:

```python
counter = 0

def increment():
    counter = counter + 1     # UnboundLocalError
```

Ключевое слово `global` снимает это ограничение, и пользоваться им не стоит.
Функция, тайком меняющая внешнее состояние, ломает главное свойство контракта:
по вызову больше нельзя понять, что произошло. Всё нужное передавайте
аргументом, всё произведённое возвращайте.

## 7. Частые ошибки

**Накопитель создан внутри цикла.** Обнуляется на каждом шаге, результат неверен,
сообщения нет.

**`print` вместо `return`.** Функция возвращает `None`, ошибка всплывает позже
и в другом месте.

**Ошибка на единицу.** `range(1, len(items))` пропускает первый элемент,
`range(len(items) + 1)` даёт `IndexError`.

**Изменяемое значение по умолчанию.** `def f(acc=[])` накапливает состояние
между вызовами.

**Изменение списка во время обхода.** Удаление элементов в цикле `for` по этому же
списку пропускает элементы. Собирайте новый список или идите по копии.

**Вложенный цикл там, где хватило бы одного прохода.** Работает, пока данных мало.
