## 1. Боль, из которой всё выросло

Программа растёт. Данные лежат в словарях, функции разбросаны по файлу,
и связь между ними держится только в вашей голове.

```python
doc = {"id": "doc01", "text": "...", "tokens": None, "cleaned": False}

def clean(doc): ...
def tokenize(doc): ...
def count(doc): ...
```

Вопросы, на которые такой код не отвечает. Можно ли вызвать `count` до `tokenize`?
Что случится, если `tokenize` вызвать дважды? Кто отвечает за то, чтобы поле
`cleaned` соответствовало действительности?

Класс отвечает на эти вопросы тем, что складывает данные и работающий с ними код
в одно место.

## 2. Класс и объект

**Класс** это описание. **Объект** это экземпляр, созданный по описанию.

```python
class Document:
    def __init__(self, doc_id, text):
        self.doc_id = doc_id
        self.text = text
        self.tokens = None

    def tokenize(self):
        self.tokens = self.text.lower().split()
        return self.tokens

    def word_count(self):
        if self.tokens is None:
            self.tokenize()
        return len(self.tokens)


doc = Document("doc01", "One two three")
print(doc.doc_id, doc.word_count())
```

`__init__` вызывается при создании объекта и задаёт начальное состояние.
`self` это ссылка на сам объект, через неё метод добирается до его полей.
В списке параметров `self` пишут, при вызове не пишут.

Обратите внимание на `word_count`: метод сам следит за тем, чтобы токены
существовали. Вызывающему больше не нужно помнить порядок вызовов.

## 3. Состояние и поведение

**Состояние** это поля объекта. **Поведение** это его методы.

Хороший класс держит состояние согласованным. Если поле `tokens` заполнено,
оно соответствует полю `text`. Как только `text` меняется, `tokens` обязаны
устареть.

```python
class Document:
    def __init__(self, doc_id, text):
        self.doc_id = doc_id
        self._text = text
        self._tokens = None

    def set_text(self, text):
        self._text = text
        self._tokens = None        # старые токены больше не действительны
```

Подчёркивание в начале имени это соглашение: «поле внутреннее, снаружи его
трогать не следует». Python это не проверяет, договорённость держится
на дисциплине.

## 4. Зона ответственности

Самое важное в теме. У класса должна быть одна внятная зона ответственности,
которую можно назвать одной фразой.

| Класс | Отвечает за |
| --- | --- |
| `Document` | один текст и его производные |
| `Tokenizer` | правила разбиения на токены |
| `Corpus` | набор документов и операции над набором |

Признак плохого класса: описание его назначения требует слова «и».
«Класс хранит документы и делает токенизацию и считает статистику и пишет отчёт»
означает четыре класса вместо одного.

Второй признак: метод, который не обращается ни к одному полю объекта.
Такой метод к классу отношения не имеет, ему место в обычной функции.

## 5. Инкапсуляция

Инкапсуляция это разделение на то, что снаружи, и то, что внутри.

Снаружи виден набор методов, которыми пользуются. Внутри лежит устройство,
которое можно менять, пока внешний набор остаётся прежним.

```python
class Tokenizer:
    def __init__(self, lowercase=True, keep_hyphens=False):
        self._lowercase = lowercase
        self._keep_hyphens = keep_hyphens

    def split(self, text):
        if self._lowercase:
            text = text.lower()
        separators = " .,!?"
        if not self._keep_hyphens:
            separators += "-"
        for ch in separators:
            text = text.replace(ch, " ")
        return [t for t in text.split() if t]
```

Настройки токенизации стали состоянием объекта. Вызывающий код больше не передаёт
их в каждый вызов, и правило применяется единообразно ко всему корпусу.

## 6. Композиция и наследование

**Композиция** это «объект содержит другой объект». Основной способ собирать
системы.

```python
class Corpus:
    def __init__(self, tokenizer):
        self._tokenizer = tokenizer          # корпус СОДЕРЖИТ токенизатор
        self._documents = []

    def add(self, document):
        self._documents.append(document)

    def vocabulary(self):
        words = set()
        for document in self._documents:
            words.update(self._tokenizer.split(document.text))
        return words
```

**Наследование** это «объект является разновидностью другого».

```python
class XmlDocument(Document):
    def clean_text(self):
        return re.sub(r"<[^>]+>", " ", self.text)
```

Правило проверки одно: подставьте фразу «X является разновидностью Y».
Если фраза звучит неестественно, наследование здесь лишнее.

`XmlDocument` является разновидностью `Document`, звучит нормально.
`Corpus` является разновидностью `Document` звучит абсурдно, поэтому корпус
документ содержит, а не наследует.

Наследованием злоупотребляют, потому что оно даёт быстрый способ переиспользовать
код. Композиция для этой цели подходит лучше и связывает классы слабее.

## 7. `__str__`

Метод, задающий текстовое представление объекта.

```python
class Document:
    def __str__(self):
        return f"Document {self.doc_id!r} ({self.word_count()} words)"

print(Document("doc01", "One two three"))
```

Без него `print` выводит адрес объекта в памяти, что при отладке бесполезно.

## 8. Когда класс не нужен

| Ситуация | Решение |
| --- | --- |
| функция без состояния | обычная функция |
| данные без поведения | кортеж, словарь, `dataclass` или `NamedTuple` |
| один экземпляр на всю программу | модуль с функциями |
| класс из одного метода | функция |

Класс оправдан там, где есть состояние, которое надо держать согласованным,
и несколько операций над ним.

## 9. Где это применяется

| Где | Что там классы |

## 10. Частые ошибки

**Класс на всё сразу.** Описание требует слова «и» три раза.

**Метод, не обращающийся к полям.** Это функция, а не метод.

**Наследование вместо композиции.** Проверьте фразой «является разновидностью».

**Изменяемое значение по умолчанию в `__init__`.** Та же ловушка, что на занятии 3:
`def __init__(self, items=[])` разделяет один список между всеми объектами.

**Публичные поля, которые обязаны быть согласованы.** Внешний код меняет `text`,
а `tokens` остаются старыми.

**Класс ради класса.** Функция из трёх строк не становится лучше от того,
что её обернули в класс.
