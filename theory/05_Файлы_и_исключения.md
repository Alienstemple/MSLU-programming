## 1. Кодировки

Компьютер хранит числа. Кодировка задаёт соответствие между числами и символами.

Юникод присваивает номер каждому символу всех письменностей. UTF-8 задаёт способ
записать эти номера байтами: латинская буква занимает 1 байт, кириллическая 2,
эмодзи до 4.

```python
ord("a")     # 97
ord("а")     # 1072, это другая буква
chr(1072)    # 'а'
len("привет".encode("utf-8"))    # 12 байт при 6 символах
```

Кодировку при открытии файла указывают явно:

```python
open(path, encoding="utf-8")
```

Без этого Python берёт системную, и код, работающий на macOS, падает на Windows
с `UnicodeDecodeError`. Выгрузки из старых Windows-программ бывают в `cp1251`.

### Визуально одинаковые символы

```python
"а" == "a"     # False, кириллица и латиница
```

Единственная ошибка курса, которую нельзя увидеть при чтении кода. На экране
символы одинаковы, сравнение даёт ложь. Сюда же относятся дефис `-`, минус `−`
и тире `–`, обычные кавычки и «ёлочки».

Способ проверить:

```python
[ord(c) for c in suspicious]
```

## 2. Чтение и запись

```python
with open(path, encoding="utf-8") as f:
    text = f.read()
```

`with` закрывает файл при выходе из блока, включая выход по исключению.

| Способ | Когда |
|---|---|
| `f.read()` | файл целиком, помещается в память |
| `f.readlines()` | список строк, каждая с `\n` на конце |
| `for line in f` | построчно, память не растёт |

Построчный обход основной. Файл на гигабайт через `read()` не пройдёт.

```python
with open(path, encoding="utf-8") as f:
    for line in f:
        line = line.rstrip("\n")
        ...
```

`rstrip("\n")` обязателен. Иначе `"word\n" == "word"` даёт `False`,
и получается «слово есть в файле, но не находится».

Режимы открытия:

| Режим | Действие |
|---|---|
| `"r"` | чтение, по умолчанию |
| `"w"` | запись, содержимое стирается |
| `"a"` | дописывание в конец |

`"w"` стирает файл сразу при открытии, до всякой записи.

## 3. Разбор записей

Строка файла обычно содержит несколько полей.

```python
with open(path, encoding="utf-8") as f:
    for line in f:
        fields = line.rstrip("\n").split(",")
        name, year, role = fields
```

Пятистрочник, который встречается чаще всего остального, и самый хрупкий.
Что произойдёт при четырёх полях вместо трёх? При годе, записанном как «около 1799»?
Про это следующий раздел.

Для настоящих CSV с кавычками и запятыми внутри полей берут модуль `csv`,
он разбирает такие случаи правильно.

## 4. Исключения

Исключение это отказ выполнить операцию вместо выдумывания результата.

```python
try:
    with open(path, encoding="utf-8") as f:
        text = f.read()
except FileNotFoundError:
    print(f"File not found: {path}")
    text = ""
```

| Исключение | Когда возникает |
|---|---|
| `FileNotFoundError` | путь не существует |
| `UnicodeDecodeError` | файл не в указанной кодировке |
| `ValueError` | `int("abc")` |
| `KeyError` | обращение к отсутствующему ключу словаря |
| `IndexError` | индекс за границей |
| `TypeError` | операция не подходит типу |
| `ZeroDivisionError` | деление на ноль |

### Как ловить

```python
try:
    year = int(fields[1])
except ValueError:
    print(f"Bad year in line: {line!r}")
    year = None
```

Ловят конкретное исключение и сообщают, что случилось.

Конструкция `except: pass` глушит всё подряд, включая ваши собственные опечатки,
и превращает падающую программу в тихо врущую. Сравните два исхода:

* программа упала на третьем файле из ста, вы об этом знаете,
* программа обработала все сто, молча пропустив тридцать битых строк,
  результат занижен на треть, в отчёте ни слова.

Второй хуже.

## 5. Стратегия для грязных данных

Плохие записи считают и показывают.

```python
processed = 0
skipped = []

for line in f:
    try:
        handle(line)
        processed += 1
    except ValueError as error:
        skipped.append((line, str(error)))

print(f"Processed {processed}, skipped {len(skipped)}")
```

Одна дополнительная переменная, и вы всегда знаете цену результата.

Реальный текстовый файл содержит двойные пробелы, неразрывные пробелы, остатки
разметки, разные виды кавычек и тире, переносы посреди предложения. Очистку
оформляют функцией, а не рассыпают по коду: функцию можно показать, обсудить
и поменять в одном месте.

Каждый шаг очистки это решение с ценой. Привели к нижнему регистру, потеряли
имена собственные. Убрали дефисы, склеили или разорвали слова. Универсально
правильной очистки не существует, есть подходящая под задачу, и вы должны уметь
перечислить, что она теряет.

## 6. Частые ошибки

**`encoding` не указан.** Работает у вас, падает у соседа.

**`"w"` вместо `"a"`.** Файл стёрт, обычно единственная копия.

**`except: pass`.** Данные теряются молча.

**`read()` на большом файле.** Память кончается.

**Забыт `rstrip("\n")`.** Сравнения и словарные ключи перестают совпадать.

**Кодировка угадана, а не проверена.** «Кракозябры» означают неверную кодировку
при чтении, сам файл обычно цел.
