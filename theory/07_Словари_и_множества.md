## 1. Словарь

Отображение ключ в значение.

```python
counts = {"a": 42, "b": 17}

counts["a"]              # 42
counts["c"] = 5          # добавили
counts["a"] += 1         # изменили
len(counts)
"a" in counts            # проверка ключа, O(1)
```

Обращение к отсутствующему ключу даёт `KeyError`. Безопасные способы:

```python
counts.get("c", 0)             # вернёт 0, если ключа нет
counts.setdefault("c", []).append(1)
```

Подсчёт частот, самый частый трёхстрочник:

```python
counts = {}
for item in items:
    counts[item] = counts.get(item, 0) + 1
```

Готовый вариант из стандартной библиотеки:

```python
from collections import Counter

counts = Counter(items)
counts.most_common(10)     # десять самых частых пар
```

Перебор:

```python
for key in counts:                    # только ключи
for key, value in counts.items():     # пары, так удобнее
```

Сортировка по значению:

```python
top = sorted(counts.items(), key=lambda p: p[1], reverse=True)[:10]
```

## 2. Множество

Неупорядоченная коллекция без повторов.

```python
unique = {"a", "b", "a"}     # {'a', 'b'}
unique = set(items)

"a" in unique                # O(1)
unique.add("c")
unique.discard("c")          # без ошибки, если элемента нет
```

Пустое множество это `set()`. Литерал `{}` создаёт пустой словарь.

Операции:

```python
a & b     # пересечение
a | b     # объединение
a - b     # разность
a ^ b     # симметрическая разность
```

## 3. Хеш-таблица

Поиск в списке из миллиона элементов требует в среднем полмиллиона сравнений.
Словарь вычисляет из ключа число (хеш) и по нему сразу знает, в какую ячейку смотреть.
Одно вычисление вместо перебора, и при росте словаря в тысячу раз время не меняется.

```python
hash("text")     # число
hash(42)
hash((1, 2))     # кортеж хешируем
hash([1, 2])     # TypeError, список нет
```

Ключом может быть только неизменяемое значение. Изменяемый ключ изменил бы свой хеш,
и значение потерялось бы в таблице навсегда. Отсюда практическая ценность кортежей
с занятия 6.

Порядок в словаре это порядок добавления. Нужен алфавитный или по частоте,
сортируйте явно.

## 4. Коллизии

Ячеек конечное число, ключей сколько угодно, поэтому два разных ключа рано или поздно
получат один номер. Это коллизия. В ячейке лежит список, и при коллизии Python
дочитывает его перебором.

Отсюда уточнение к слову «мгновенно»:

* в среднем поиск O(1),
* в худшем случае, когда все ключи попали в одну ячейку, O(n).

Худший случай на практике не встречается: хеш-функция хорошая, таблица расширяется
при заполнении больше чем на две трети. Расширение дорого и происходит редко,
в пересчёте на одну вставку остаётся O(1).

Вывод: O(1) у словаря это обещание в среднем. Для прикладных задач разницы нет,
знать про это стоит, чтобы понимать чужой код.

## 5. Сортировка подсчётом

Счётчик работает и как алгоритм сортировки. Отсортировать миллион значений
из диапазона 1..5 сравнениями означает O(n log n). Сравнивать здесь нечего,
достаточно посчитать, сколько каких.

```python
def counting_sort(values, low, high):
    counts = [0] * (high - low + 1)
    for value in values:
        counts[value - low] += 1

    result = []
    for i, count in enumerate(counts):
        result.extend([i + low] * count)
    return result
```

Сложность O(n + k), где k размер диапазона. Ни одного сравнения элементов.

Условие применимости одно: значения целые из небольшого известного диапазона.

| Данные | Подходит |
|---|---|
| оценки 1..5, возраст 0..120, длины слов | да |
| зарплаты, частоты | нет, диапазон огромен |
| строки, даты, дробные числа | нет |

Массив счётчиков это одновременно и гистограмма распределения.
Сортировка и построение распределения делаются одним проходом.

Поразрядная сортировка (занятие 19) применяет сортировку подсчётом несколько раз
подряд и снимает ограничение на диапазон.

## 6. Выбор структуры

| | list | set | dict |
|---|---|---|---|
| порядок | да | нет | по добавлению |
| повторы | да | нет | ключи уникальны |
| доступ | по индексу | только проверка наличия | по ключу |
| `x in c` | O(n) | O(1) | O(1) по ключу |
| главный вопрос | что третье по счёту | есть ли такое | что связано с этим |

```
нужно связать одно с другим        -> dict
нужно только знать, есть ли        -> set
важен порядок или нужны повторы    -> list
```

## 7. Частые ошибки

**`{}` для пустого множества.** Это пустой словарь, множество это `set()`.

**Обращение по отсутствующему ключу.** `KeyError`, лечится `get` с умолчанием.

**Ожидание алфавитного порядка от словаря.** Порядок это порядок добавления.

**Список как ключ.** `TypeError: unhashable type`.

**`in` по списку там, где нужно множество.** На ста элементах незаметно,
на ста тысячах разница в сотни раз.

**Счётчик со значением 0 не удалён.** `len(counts)` начинает врать.
При работе с окном (занятие 20) это критично.
